# Features and Functionality

This document exists because the assignment states that undocumented features will not be considered.

## 1. Todo list page — `index.html`

- Create a todo with title, description, priority, due date, and tags.
- Display all todos returned by the backend.
- Mark a todo completed/active directly from the list.
- Delete a todo with a confirmation step.
- Search across title, description, and tags.
- Filter by completion status.
- Filter by priority.
- Sort by newest, oldest, due date, or priority.
- Display visible/active/completed counters.
- Highlight overdue todos.
- Responsive layout for desktop and mobile.
- Loading, empty, success, and error feedback states.

## 2. Todo detail page — `todo.html?id=<todo-id>`

- Reads the todo id from the URL query parameter using `URLSearchParams`.
- Fetches one todo with `GET /api/todos/:id`.
- Displays title, description, status, priority, due date, tags, ID, creation time, and last-update time.
- Edit todo details in place.
- Mark completed/active.
- Delete the todo and return to the list page.
- Handles a missing `id` query parameter explicitly.
- Handles a missing/non-existent todo cleanly.

## 3. Backend

- Express.js REST API.
- CRUD operations for todos.
- JSON body validation with readable `400` errors.
- `404` handling for unknown todos and routes.
- File persistence in `data/todos.json`.
- Atomic writes via a temporary file before rename to reduce the chance of partial file corruption.
- UUID ids generated by Node's built-in `crypto.randomUUID()`.
- CORS enabled for local frontend/backend development.
- Search, filter, and sort query parameters are implemented server-side.
- Health endpoint at `GET /api/health`.

## 4. Small touches intended to stand out

The project stays within the requested scope rather than becoming an oversized product, but adds practical product-quality details: responsive UI, useful metadata, validation, overdue visibility, URL-driven detail pages, server-side filtering/sorting, atomic file persistence, explicit error states, and clear Markdown documentation.
